# BridgePad wire protocol v1

Status: **draft 1.0**. This document defines the transport-independent control
protocol shared by the Android client and BridgePad Desktop. Multi-byte values
use network byte order (big-endian). The protocol never serializes Kotlin or
Rust objects directly.

This draft covers framing, capability negotiation, session lifecycle, controller
snapshots, pointer input, health messages, status, errors and rumble. Pairing,
authentication and encryption are intentionally not specified yet. A transport
must not expose this draft to an untrusted network.

## Packet envelope

Every stream transport reads the fixed 32-byte header first and then exactly
`payload_length` bytes. Datagram transports put one complete packet in each
datagram.

| Offset | Size | Field | v1 value or meaning |
| ---: | ---: | --- | --- |
| 0 | 4 | magic | ASCII `BPD1` (`0x42504431`) |
| 4 | 1 | major version | `1` |
| 5 | 1 | minor version | `0` |
| 6 | 1 | message type | See message table |
| 7 | 1 | flags | `0`; other values are rejected in draft 1.0 |
| 8 | 8 | session ID | Unsigned identifier; `0` before a session exists |
| 16 | 4 | sequence | Unsigned counter, wrapping after `0xffffffff` |
| 20 | 8 | timestamp | Sender monotonic time in microseconds |
| 28 | 2 | payload length | Unsigned, maximum 4096 |
| 30 | 2 | reserved | Must be zero |

The current Kotlin codec accepts session IDs and timestamps up to signed 64-bit
maximum. Receivers reject a bad magic value, unsupported version, flags,
reserved bytes, oversized payload, truncation and trailing bytes.

## Capabilities

Capabilities are an unsigned 32-bit bit set. Unknown bits must be preserved
during negotiation but must not be enabled unless both peers advertise them.

| Bit | Capability |
| ---: | --- |
| 0 | Gamepad |
| 1 | Pointer |
| 2 | Rumble |
| 3 | Video (reserved for a later protocol extension) |
| 4 | Audio (reserved for a later protocol extension) |

## Message types and payloads

Strings are strict UTF-8. `string8` has a one-byte length prefix; `string16`
has a two-byte length prefix.

| Type | Name | Payload |
| ---: | --- | --- |
| `0x01` | Hello | peer ID (16), capabilities (u32), peer name (string8, max 64 bytes), app version (string8, max 32 bytes) |
| `0x02` | HelloAck | Same fields as Hello |
| `0x03` | SessionStart | input kind (u8), requested capabilities (u32) |
| `0x04` | SessionReady | enabled capabilities (u32) |
| `0x05` | SessionStop | stop reason (u8) |
| `0x10` | GamepadSnapshot | Complete 15-byte gamepad state |
| `0x11` | Pointer | buttons (u8), delta X (i32), delta Y (i32) |
| `0x20` | Ping | nonce (u64) |
| `0x21` | Pong | nonce copied from Ping (u64) |
| `0x30` | Status | status code (u8), diagnostic detail (string16) |
| `0x31` | Error | stable error code (u16), fatal boolean (u8: 0 or 1), diagnostic detail (string16) |
| `0x40` | Rumble | low motor (u16), high motor (u16), duration milliseconds (u16) |

Input kinds are `0` touchscreen and `1` physical gamepad. Session stop reasons
are `0` user request, `1` client shutdown, `2` receiver shutdown, `3` transport
lost and `4` protocol error.

Status codes are `0` idle, `1` connecting, `2` ready, `3` active and `4`
degraded. Error codes are `1` unsupported version, `2` invalid message, `3`
capability mismatch, `4` session rejected and `5` internal error. Interfaces
localize these codes; diagnostic detail is not user-facing copy.

## Gamepad snapshot

Each snapshot contains the full current state so a later snapshot can recover
from packet loss. Its 15-byte payload is:

| Offset | Size | Field |
| ---: | ---: | --- |
| 0 | 2 | Button bit set |
| 2 | 1 | D-pad direction |
| 3 | 2 | Left X, signed normalized i16 |
| 5 | 2 | Left Y, signed normalized i16 |
| 7 | 2 | Right X, signed normalized i16 |
| 9 | 2 | Right Y, signed normalized i16 |
| 11 | 2 | Left trigger, unsigned normalized u16 |
| 13 | 2 | Right trigger, unsigned normalized u16 |

Signed axes encode `-1.0..1.0` as `-32767..32767`. Triggers and rumble encode
`0.0..1.0` as `0..65535`.

Button bits 0 through 15 are, in order: face south, face east, face west, face
north, left bumper, right bumper, start, select, left stick button, right stick
button and extra buttons 1 through 6. D-pad values are `0` neutral, then `1`
through `8` clockwise from north: north, north-east, east, south-east, south,
south-west, west and north-west.

## Session flow

The basic state flow is:

```text
transport connected
  -> Hello
  <- HelloAck
  -> SessionStart
  <- SessionReady
  <-> input snapshots, pointer reports, Ping/Pong, Status and Rumble
  -> or <- SessionStop
```

The receiver enables only the intersection of supported and requested
capabilities. It discards duplicate or older input sequences. A heartbeat
timeout must release every button and remove or neutralize the virtual device.
Exact heartbeat and recovery timing will be fixed after desktop transport
measurements.

## Golden vector

The normative machine-readable vectors live in
[`vectors/v1.properties`](vectors/v1.properties). The Ping vector has session
ID 1, sequence 2, timestamp 3 and nonce 4:

```text
42504431010020000000000000000001000000020000000000000003000800000000000000000004
```

The Kotlin suite encodes and decodes this vector. The Rust codec must consume
the same bytes before the draft can pass Gate D0.

## Work still required before network use

- Choose the authenticated encrypted channel after Wi-Fi/USB latency spikes.
- Define pairing request, challenge and result payloads without custom crypto.
- Define minor-version and optional-message compatibility behavior.
- Fix heartbeat, resynchronization and reconnect timing from measurements.
- Add shared Kotlin/Rust vectors, reorder/loss tests and desktop decoder fuzzing.
